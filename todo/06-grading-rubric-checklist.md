# เช็กลิสต์ QA ตามตารางที่ 2-57 "หน้าที่รับผิดชอบ" (หน้า 335–341)

รายการทั้งหมด 35 รายการ ที่ระบุ วัตถุประสงค์ ขนาด/หน่วย และเกณฑ์การตรวจสอบ (การตรวจสอบ) ของแต่ละส่วนในรายงาน
ใช้ไฟล์นี้ตรวจทานคุณภาพเนื้อหาก่อนส่ง แยกจากเช็กลิสต์หัวข้อ (ไฟล์ 01–05) ที่ใช้ติดตามว่าเขียนหัวข้อครบหรือยัง

- [ ] 1. สารบรรณ — ใช้ในการหาเอกสารอื่นๆ (1 ชุด) — ต้องมีสารบรรณที่ระบุหน้าเอกสารที่ส่งทุกรายการ
- [ ] 2. รูป — อ้างอิงรูป (1 ชุด) — ต้องมีเลขรูปอยู่ พร้อมระบุว่าเป็นรูปอะไร
- [ ] 3. ตาราง — อ้างอิงตาราง (1 ชุด) — ต้องมีเลขตาราง พร้อมระบุว่าเป็นตารางอะไร
- [ ] 4. บทนำ — แนะนำหน่วยงาน ที่มาที่ไปของหน่วยงาน (0.5 หน้า) — ไม่ใช้ภาษาพูด เขียนจับใจความได้ มีการอ้างอิงถึงหน่วยงานที่จะไปพัฒนาระบบให้ ว่าประสบปัญหาอย่างไร
- [ ] 5. ปัญหา — ประเด็นปัญหาที่ต้องการจะแก้ไขโดยใช้ Application (0.5 หน้า) — แสดงข้อมูลอภิปรายถึงปัญหาอย่างชัดเจน แต่ไม่ใช่การบอกว่าระบบมีปัญหาเนื่องจากไม่ได้ใช้ระบบคอมพิวเตอร์ โดยควรจะมีตัวเลขสนับสนุน เช่น ทำงานช้า ใช้เวลา 2 ชั่วโมงในการตรวจสอบยอดคลังสินค้า
- [ ] 6. Business Process เดิม — Business Process (1 รูป) — สัญลักษณ์ถูกต้อง ชื่อต้องเป็น verb อ่านแล้วต้องชัดเจน (เช่น "ตรวจสอบ" ไม่ชัดเจนว่าตรวจสอบอะไร ควรแก้เป็น "ตรวจสอบสินค้าถึงจุดสั่งซื้อ") สวยงามดูสบายตา มีช่องไฟที่ดี แสดง logic จากบนลงล่างและซ้ายไปขวา มีเลข Process
- [ ] 7. คำอธิบาย Business Process เดิม — อธิบาย Business Process (0.5 หน้า) — อธิบายการทำงานของ Business Process ตั้งแต่เริ่มจบครบทุกขั้นตอน โดยระบุ ใครทำอะไร ได้ผลอะไร
- [ ] 8. ปัญหา (ของ Business Process เดิม) — อธิบายให้ทราบถึงปัญหาหลักๆ ของระบบ อาจมีการคำนวณให้เข้าใจถึงขนาดของปัญหา (0.5 หน้า) — เป็นปัญหาที่เกิดขึ้นกับระบบเดิม และสามารถแก้ไขได้โดยระบบใหม่ด้วยคอมพิวเตอร์ ต้องระบุว่าปัญหาคือการไม่ใช้คอมพิวเตอร์ในการทำงาน และปัญหานี้ต้องจัดและตรวจสอบได้ว่าจะหายไปหรือลดลงเมื่อใช้ระบบคอมพิวเตอร์
- [ ] 9. Business Process ใหม่ — Business Process ใหม่ (รูปต้องชี้ให้เห็นว่าปรับปรุงที่ processes ใด) (1 รูป) — สัญลักษณ์ถูกต้อง ชื่อต้องเป็น verb อ่านแล้วไม่เข้าใจว่าทำอะไร สวยงามดูสบายตา มีช่องไฟที่ดี เส้นตัดกันน้อยที่สุด แสดง logic จากบนลงล่างซ้ายไปขวา มีเลข Process
- [ ] 10. คำอธิบาย Business Process ใหม่ — เขียนบรรยายว่าระบบใหม่มีปรับปรุงอะไรบ้าง (0.5 หน้า) — อธิบายการทำงานของ Business Process ตั้งแต่เริ่มจบครบทุกขั้นตอน โดยระบุ ใครทำอะไร ได้ผลอะไร และระบุว่า Process ใดเป็น manual และกระบวนการใดที่แก้ไขปัญหาในข้อปัญหา
- [ ] 11. Business Process ที่สัมพันธ์กับ use case — แสดงการวิเคราะห์เพื่อแปลงเป็น use case (1 รูป) — แสดง use case บน business process ทั้ง uc ที่เป็น computer และ manual
- [ ] 12. ตารางจับคู่ระหว่าง BP & UC — แสดงความสัมพันธ์ของ UC และ BP (1 tables) — ทุก UC ต้องมาจาก BP
- [ ] 13. Use case diagram ก่อนปรับปรุง — รูป UC ที่ได้จากการวิเคราะห์จาก BP (5 UC) — แสดง actor ตาม swim lane ชื่อต้องตรงกับรูป Business Process มีเลขกำกับ uc
- [ ] 14. CRUD Table — ตารางแสดงความสัมพันธ์ระหว่าง UC/Entities (1 tables) — แสดง uc ทั้งหมด และ Entity ที่สำคัญๆ ในระบบจากการวิเคราะห์ noun ในกระบวนการทำงาน
- [ ] 15. คำอธิบายประกอบตาราง CRUD — คำอธิบายการวิเคราะห์ตาราง CRUD (0.5 หน้า) — คำอธิบายแสดงการวิเคราะห์ และชี้ประเด็นให้ได้ว่าจากการวิเคราะห์แล้วยังขาด uc อะไร
- [ ] 16. Use case diagram ที่ทบทวนปรับปรุงแล้ว — UC diagram ที่แก้ไขเพิ่มเติมจากการวิเคราะห์ CRUD Table (1 รูป) — uc ที่เพิ่มเติมจากการวิเคราะห์
- [ ] 17. CRUD Table ทบทวน — ตารางแสดงความสัมพันธ์ระหว่าง UC/Entities ที่ทบทวนแล้ว พร้อมคำอธิบาย (1 tables) — ตารางใหม่ที่ได้เพิ่ม uc และ CRUD ในระบบ
- [ ] 18. Use case description — แสดง logic การทำงานของแต่ละ uc (5 UC) — แสดง actor ตาม uc, แสดง logic ของ system/actor สอดคล้องกับ user interface, query แสดงใน ERD ได้อย่างถูกต้อง การจัดการเนื้อหาควรจะให้ uc description หนึ่ง ตามด้วย sequence diagram และการเรียงลำดับให้เรียน uc desc แต่ละอันตามด้วย sequence และ collaboration และไม่ควรจะแสดงแยก uc desc จนครบแล้วจึงค่อยไป diagram อื่น เพราะจะทำให้ดูยาก
- [ ] 19. ER Diagram — และข้อมูลที่ใช้ในระบบ (5 entities) — ชื่อตรงกับ CRUD, มี PK/FK, relationship (ต้องไม่ซ้ำ), cardinality (ไม่ควรมี m:m ถ้ามีจะต้องแสดง ERD ที่เป็น logical schema อีกรูปหนึ่ง), total/partial participation
- [ ] 20. ER Diagram ที่มี query — แสดงความสัมพันธ์ระหว่าง uc กับ ERD ว่า query กระทำกับ entity ใด (1 รูป) — แสดง query บน erd โดย ERD แสดงเฉพาะ entity-pk-fk เท่านั้น ยกเว้นกรณี updatedQuery ให้แสดง attribute(s) ที่ถูก update ด้วย
- [ ] 21. Query table — แสดง queries ทั้งหมด และ uc ของแต่ละ query (1 tables) — แสดง query id, uc id, uc name, sql command
- [ ] 22. Table structure — แสดง data dictionary ของทุก table (5 tables) — กลุ่มใดที่มีตารางน้อยก็จะถูกลดทอนตามสัดส่วน โดยประกอบไปด้วย attribute name, description, PK/FK, Not null?, data type (size), range of data หรือการตรวจสอบความถูกต้อง, ตัวอย่างข้อมูลอย่างน้อย 5 รายการ
- [ ] 23. Sequence Diagram — แสดง logic การทำงานของแต่ละ uc ในรูปแบบลำดับเวลาการทำงาน (10 diagram) — แสดงการทำงานร่วมกันของ object(class) ต่างๆ โดย obj ที่ติดกับ actor ต้องเป็น user interface ห้ามใช้ชื่อว่า view และการเชื่อมต่อกับ db ควรใช้ database connect และแสดงให้เห็นจริงๆ ว่าโปรแกรมใช้
- [ ] 24. Collaboration diagram — แสดง logic การทำงานของแต่ละ uc ในรูปแบบ messaging (10 diagram) — แปลงจาก sequence diagram, object ต้องตรงกับ sequence diagram, ต้องมีเลขกำกับ message
- [ ] 25. Class diagram — แสดงโครงสร้างของคลาสในระบบ (10 classes) — Obj ทุกรายการในทุก sequence diagram จะต้องถูก abstraction เป็นคลาสในรูปนี้ และกำหนดความสัมพันธ์ของคลาสเป็น super/sub, aggregation, dependency และ association แต่ละคลาสมี attribute และ method
- [ ] 26. State Diagram — แสดง obj.state ที่สำคัญๆ ของระบบ (1 diagram) — ต้องกำหนดให้ state เป็น class.state โดยระบุ class การเปลี่ยนจะกำหนดโดย [condition]event/action โดย action จะต้องเป็นชื่อ uc และเมื่อมีการเปลี่ยนค่า state จะต้องปรับปรุงใน db โดยคำสั่ง SQL
- [ ] 27. Component diagram — แสดงการรวม class เพื่อ compile (1 diagram) — มีรูปแสดง class ทั้งหมด และ library/API ที่ใช้
- [ ] 28. SW development platform — แสดง platform ของเครื่องมือต่างๆ ที่ใช้ (1 รูป) — แสดงรูปของเครื่องมือส่งๆ ที่ใช้ในการพัฒนา (Stack of tools)
- [ ] 29. Site map/UI structure — แสดงโครงสร้างของ application (8 screen) — แสดงเป็น tree โดย root คือ login และให้แสดง tree ของแต่ละผู้ใช้
- [ ] 30. User interface design — แสดงหน้าจอการทำงานของ actor (8 screen) — แสดง screen ทั้งหมดให้กำหนดชื่อแจงแต่ละ screen ตาม uc name
- [ ] 31. Output design (report) — แสดงรายงานทั้งหมดในระบบ (2 reports) — แสดงโครงสร้างของ report และตัวอย่างของรายงานที่ได้บันทึกข้อมูลผ่าน uc ต่างๆ
- [ ] 32. SQL Statement ใน UC description — แสดง SQL command ทั้งหมดในระบบ (10 statements) — แสดง Query number, uc id, sql command
- [ ] 33. การทดสอบโปรแกรมทำงานตาม UC description — แสดงผลการทดสอบโปรแกรมต่างๆ (8 tables) — แสดง uc id, uc name, capture screen แสดงการบันทึกและการออกรายงานทั้งหมด
- [ ] 34. ความพร้อม — แสดงความพร้อมของการนำเสนอ (1 งาน) — มีสไลด์ (มีเลขหน้าสไลด์), รายงาน (pdf, word) และโปรแกรมพร้อมทำงาน และสมาชิกทุกคนออนไลน์ และเปิดกล้องได้ หากไม่เปิดกล้องจะหัก 50%
- [ ] 35. คะแนนการทำงาน — แสดงการแบ่งงานและผลการทำงาน (1 งาน) — มีคะแนนการทำงานของทีมงานโดยหัวหน้า ตามรูปแบบที่กำหนด
